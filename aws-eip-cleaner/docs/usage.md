# aws-eip-cleaner 利用者ガイド

`aws-eip-cleaner` は、AWS アカウント上の未利用 Elastic IP（EIP）を検出して解放する CLI ツールです。複数リージョンを並列に調査し、検出した未利用 EIP を一覧表示したうえで、対話確認・一括解放・ドライランのいずれかのモードで解放を行います。

## 前提条件

### 実行環境

- Python 3.14 以上
- パッケージ／環境管理に [uv](https://docs.astral.sh/uv/) を使用します。

### AWS 認証情報

本ツールは boto3（botocore）の標準的な認証情報解決に従います。次のいずれかで認証情報を用意してください。

- 環境変数（`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / 必要に応じて `AWS_SESSION_TOKEN`）
- 共有認証情報ファイル（`~/.aws/credentials`）と設定ファイル（`~/.aws/config`）のプロファイル
- インスタンスプロファイルや SSO など、boto3 が解決できるその他の認証ソース

`--profile` オプションで特定のプロファイル名を指定できます。無指定の場合は boto3 の標準認証情報解決チェーンが使われます。

必要な IAM 権限は次のとおりです。

- `ec2:DescribeAddresses`（未利用 EIP の調査に使用）
- `ec2:ReleaseAddress`（EIP の解放に使用。dry-run では不要）

## インストール

リポジトリを取得し、ツールのディレクトリで依存関係を同期します。

```bash
git clone <repository-url>
cd kiro-university-challenge/aws-eip-cleaner
uv sync
```

`uv sync` により、実行に必要な依存（boto3 など）が仮想環境へインストールされます。

## 実行方法

`uv run` 経由でモジュールとして起動します。

```bash
uv run python -m aws_eip_cleaner [オプション]
```

`aws-eip-cleaner` ディレクトリ内で実行してください。仮想環境を有効化済みであれば、`python -m aws_eip_cleaner [オプション]` でも起動できます。

ヘルプは次で確認できます。

```bash
uv run python -m aws_eip_cleaner --help
```

`--help` を指定すると、各オプションの説明を標準出力に表示して終了コード 0 で終了します（調査・解放は行いません）。

## CLI オプション一覧

| オプション | 形式 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `--region` | 値を取る（繰り返し指定可） | 指定なし（全リージョン） | 調査対象のリージョンを指定します。複数回指定して複数リージョンを対象にできます。重複して指定した場合は 1 件に統合されます。無指定時はアクセス可能な全リージョンを対象とします。 |
| `--profile` | 値を取る | `None`（標準チェーン） | 使用する AWS 認証プロファイル名を指定します。無指定時は boto3 標準の認証情報解決に従います。 |
| `--dry-run` | フラグ（値なし） | 無効 | 解放を一切行わず、対象となる EIP の一覧を表示するのみとします。対話確認も行いません。 |
| `--yes` | フラグ（値なし） | 無効 | 確認プロンプトを省略し、検出した EIP を一括で解放します。 |

### オプションの補足

- `--region` を 1 つも指定しない場合、認証情報でアクセス可能な全リージョンを調査対象にします。
- `--region` の指定回数（重複排除前）が 50 回を超えるとエラーになり、調査を行わずに非ゼロの終了コードで終了します（50 回までは許容）。
- `--region` に、boto3 の EC2 既知リージョン一覧（`Session.get_available_regions("ec2")`）に含まれない値を 1 つでも指定するとエラーになり、調査を行わずに非ゼロの終了コードで終了します。
- `--dry-run` と `--yes` は同時に指定できません。両方を指定した場合は排他である旨のエラーを表示し、いかなる EIP も解放せずに終了コード 2 で終了します。
- いずれのオプションも指定しない場合は、全リージョンを対象に調査し、検出した EIP を 1 件ずつ対話確認しながら解放します（対話モード）。

## 実行モード

指定したオプションに応じて 3 つのモードのいずれかで動作します。

- **対話モード**（`--dry-run` も `--yes` も指定しない場合、既定）
  検出した未利用 EIP を 1 件ずつ提示します。承認は `y`、拒否は `n` の 1 文字入力（大文字・小文字は区別しません）で答えます。承認した EIP のみ解放します。無効な入力の場合は同一の EIP について最大 3 回まで再入力を求め、3 回連続で無効なら拒否として扱って次へ進みます。標準入力が閉じた（EOF）場合は、残りの EIP を解放せずに処理を終了します。
- **ドライランモード**（`--dry-run`）
  検出した EIP の一覧と合計件数を表示するだけで、解放も対話確認も行いません。
- **一括解放モード**（`--yes`）
  対話確認を省略し、検出した全 EIP を解放します。開始時に解放対象の総数を、完了時に解放成功件数と解放失敗件数を表示します。

いずれのモードでも、調査完了後にまず検出した未利用 EIP の一覧を表示します。検出が 0 件の場合は、対象が存在しない旨のメッセージを表示し、解放を行わずに終了コード 0 で終了します。

## 使用例

### 全リージョンをドライランで確認する

解放は行わず、アクセス可能な全リージョンの未利用 EIP を一覧表示します。

```bash
uv run python -m aws_eip_cleaner --dry-run
```

### 特定リージョンを対象に調査する

`--region` を繰り返し指定して対象リージョンを絞り込みます。

```bash
uv run python -m aws_eip_cleaner --region us-east-1 --region ap-northeast-1
```

上記はデフォルトの対話モードで動作します。1 件ずつ確認して解放します。

### 認証プロファイルを指定する

```bash
uv run python -m aws_eip_cleaner --profile my-profile --region us-east-1
```

### 確認をスキップして一括削除する

対話確認を行わず、検出した全 EIP を解放します。誤操作を防ぐため、まず `--dry-run` で対象を確認してから実行することを推奨します。

```bash
uv run python -m aws_eip_cleaner --yes --region us-east-1
```

## 未利用 EIP の定義

本ツールにおける「未利用 EIP（Unused EIP）」とは、いずれのリソース（EC2 インスタンスや ENI）にも関連付けられていない割り当て済みの EIP を指します。具体的には、`describe-addresses` で列挙されるアドレスのうち **Association ID を持たない**（Association ID が未設定または空文字である）ものを未利用とみなします。

検出した各未利用 EIP について、次の 4 項目を 1 件 1 行で表示します。

- Allocation ID（例: `eipalloc-xxxx`）
- パブリック IP アドレス
- リージョン
- 関連付け状態（未利用 EIP は「関連付けなし」と表示）

一覧の末尾には合計件数（`合計: N 件`）を表示します。件数の打ち切りは行わず、検出した全件を表示します。

## 終了コードの意味

| 終了コード | 意味 |
| --- | --- |
| `0` | 正常終了。検出 0 件、ドライラン、または全件が解放成功・調査失敗なしの場合。 |
| `1`（非ゼロ） | 解放に失敗した EIP が 1 件以上ある、いずれかのリージョンの調査が失敗した、または認証失敗・プロファイル不在・リージョン列挙失敗・無効／過多なリージョン指定などツール固有のエラーが発生した場合。 |
| `2` | コマンドラインオプションの問題。未知のオプション、値の形式不正、`--yes` と `--dry-run` の同時指定など。 |

補足:

- `--help` を指定した場合は終了コード 0 で終了します。
- 一部リージョンの調査に失敗しても、成功したリージョンの結果は集約に含めて処理を継続します。ただしこの場合、最終的な終了コードは非ゼロになります。
- 一括解放モード・対話モードのいずれでも、解放に失敗した EIP が 1 件でもあれば終了コードは非ゼロになります。すべて成功すれば 0 です。

## 注意事項

- **EIP の解放は取り消せません。** 解放した EIP は失われ、同じアドレスを再取得できる保証はありません。実行前に対象を十分に確認してください。
- 事前に `--dry-run` で対象を確認してから実際の解放を行うことを強く推奨します。
- `--yes` は確認プロンプトを省略するため、意図しない EIP まで解放するおそれがあります。対象リージョンを `--region` で限定するなど、慎重に使用してください。
- リージョン調査は最大 16 並列で実行されます。あるリージョンの調査が失敗しても、他リージョンの調査・解放処理は継続します。
- 解放時のリトライ可能な API エラー（スロットリングなど）は、boto3 標準のリトライ機構により合計 3 回まで再試行されます。認証失敗や割り当て ID 不正などのリトライ不能なエラーは再試行せず失敗として扱います。
- 解放の成功は Allocation ID とともに INFO レベル、失敗は Allocation ID およびエラー内容とともに ERROR レベルでログ出力されます。
