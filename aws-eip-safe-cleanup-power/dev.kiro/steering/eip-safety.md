# 未使用 EIP を扱うときの安全指針

未使用の Elastic IP（EIP）を検出・解放する作業を行うときは、次を守る。

## 破壊的操作の扱い

- `release-address`（EIP の解放）は**不可逆**。解放した IP は二度と取り戻せない。破壊的操作として扱い、実行前に対象一覧をユーザに提示して明示承認を得る。
- `describe-addresses` / `describe-regions` など読み取り専用の検出は承認なしで進めてよい。

## 判定の原則

- 未使用候補は「`AssociationId` を持たない割り当て済み EIP」。ただし機械的に消さない。
- 次は候補から除外、または要確認とする: BYOIP（`PublicIpv4Pool != amazon`）、停止中インスタンス用の予約、IaC 管理、allowlist / DNS 登録済みの IP。

## 手順の原則

- 監査は**全リージョン**で行う（見落とし課金はたいてい未使用リージョン）。
- 実行は必ず**ドライラン → 対話確認 → （必要なら）一括**の順。一括自動はユーザの明示合意があるときのみ。
- 認証情報の値は出力しない。プロファイル名・アカウント ID の参照に留める。
- 失敗した解放を成功として報告しない。成功/失敗件数と理由を正確に伝える。

詳細な根拠と手順は Power のスキル `safe-cleanup`（`skills/safe-cleanup/`）とその `references/` を参照する。
