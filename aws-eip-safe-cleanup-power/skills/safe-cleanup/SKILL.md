# 未使用 EIP を安全に削除する

未使用の Elastic IP（EIP）は課金対象になる。ただし「未使用」の判定を誤ると、稼働中のシステムから IP を剥がしてしまう事故につながる。このスキルは検出から解放までを安全側に倒して進めるための手順を定義する。

前提知識（課金の仕組み、判定基準、落とし穴、コマンド）は `references/` にまとめてある。作業に入る前に該当ファイルを読むこと。

- `references/eip-billing.md` — 課金の仕組みと「なぜ解放が必要か」
- `references/detection-criteria.md` — 「未使用」の正確な判定基準と誤検出の罠
- `references/release-procedure.md` — 解放手順・API・リトライ・冪等性
- `references/safety-guardrails.md` — 誤削除を防ぐためのガードレール
- `references/aws-cli-cheatsheet.md` — 実行に使う AWS CLI / boto3 の具体例

## 基本原則

1. **削除ではなく「解放（release）」である。** disassociate（関連付け解除）だけでは課金は止まらない。`release-address` で割り当てそのものを返却して初めて停止する。
2. **未使用判定は Association ID の有無で行う。** `describe-addresses` の結果で `AssociationId` を持たない割り当て済み EIP を候補とする。ただし後述の例外（セカンダリ ENI、停止中インスタンス）に注意する。
3. **必ず全リージョンを調べる。** EIP はリージョンごとに割り当てられる。課金の見落としはたいてい「使っていないリージョン」で起きる。
4. **本番実行の前に必ずドライランで一覧を確認する。** 解放は不可逆で、同じ IP アドレスは二度と取得できない。
5. **一括自動解放は最終手段。** 対象を人間が確認できる規模なら対話確認を優先する。

## 標準ワークフロー

### ステップ 1: 対象範囲を決める

- 特定リージョンだけを見るのか、全リージョンを監査するのかを決める。
- 原則として初回監査は全リージョンで行い、見落とし課金を洗い出す。

### ステップ 2: 未使用 EIP を検出する（読み取りのみ）

- `describe-addresses` で割り当て済み EIP を全件列挙する。
- `AssociationId` を持たないものを未使用候補として抽出する。
- 各候補について `AllocationId` / `PublicIp` / リージョン / 関連付け状態を記録する。
- 判定の詳細と例外は `references/detection-criteria.md` を必ず参照する。

### ステップ 3: ドライランで一覧を提示する

- 検出した候補を 1 件 1 行で、件数合計とともに提示する。
- この時点では一切解放しない。
- 0 件なら「解放対象なし」と伝えて終了する。

### ステップ 4: 各候補の安全性を確認する

`references/safety-guardrails.md` のチェックリストに沿って確認する。特に以下を疑う。

- そのリージョン・アカウントに本当に不要か。
- 停止中（stopped）の EC2 インスタンスに再アタッチ予定はないか。
- allowlist（IP 許可リスト）や DNS、外部連携先に登録された固定 IP ではないか。
- BYOIP（持ち込み IP）ではないか。

### ステップ 5: 解放する

- 既定は **対話確認**（1 件ずつ承認）。
- 大量で確認が現実的でない場合のみ、明示合意のうえで一括解放する。
- 解放は `release-address` に `AllocationId` を渡して行う。
- スロットリング等のリトライ可能エラーは指数バックオフで最大 3 回まで再試行する。手順は `references/release-procedure.md` を参照。

### ステップ 6: 結果を集計する

- 成功件数・失敗件数を報告する。
- 失敗した対象は識別子（AllocationId / PublicIp / リージョン）と理由を残す。
- 1 件でも失敗があれば非ゼロ終了として扱い、ユーザに再確認を促す。

## このリポジトリの関連ツール

本リポジトリには、上記ワークフローを CLI として実装した `aws-eip-cleaner`（`../aws-eip-cleaner/`）がある。ワークフローの各ステップは同ツールのオプション（`--region` / `--profile` / `--dry-run` / `--yes`）に対応する。実装や仕様に踏み込む場合は同ツールの spec（`.kiro/specs/aws-eip-cleaner/`）を参照する。
